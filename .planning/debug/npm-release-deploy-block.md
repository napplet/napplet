# Debug Session: npm-release-deploy-block

## Symptoms

- Expected behavior: versions generated by Version Packages #207 publish to npm and JSR through GitHub Actions after repository repair #208.
- Actual behavior: JSR #186 failed on a repository workspace defect now fixed on `main`; npm Publish #210 failed with `E404` publishing existing `@napplet/core@0.32.0`; the #208 push coincided with a GitHub Actions major outage and did not create npm/JSR publish runs.
- Error messages: npm returned `404 Not Found - PUT https://registry.npmjs.org/@napplet%2fcore`; GitHub reports hosted-runner acquisition failures and delayed queues.
- Timeline: package publish failures began at commit `de1cb7e` on 2026-08-26; repair #208 merged as `11e07ee` during the Actions incident.
- Reproduction: run npm Publish with the current workflow credential, or manually dispatch Publish to JSR while Actions is degraded.

## Current Focus

- bug_class: heisenbug-mandelbug (external CI availability and npm authorization state vary outside repository code)
- reasoning_checkpoint:
    hypothesis: "The release is blocked by two independent causes: JSR's recursive command selects skills/deno.json instead of its intended jsr.json, and npm's current workflow credential lacks authority to publish @napplet/core."
    confirming_evidence:
      - "JSR run 32993805758 published core 0.32.0, then named packages/skills/deno.json as missing a license; the alternate skills/jsr.json has MIT and passes an explicit-config dry run for 0.3.2."
      - "npm Publish #210 attempts 1 and 2 both built successfully and failed at the same registry PUT E404 for @napplet/core@0.32.0."
    falsification_test: "A successful npm publish using the unchanged current credential, or a JSR default-config dry run that selects jsr.json, would disprove the respective cause."
    fix_rationale: "Explicitly publish skills with --config jsr.json preserves its separate Deno CLI configuration while using the validated JSR metadata; only an npm scope/package administrator can restore token authority or configure a trusted publisher."
    blind_spots: "The current GitHub credential cannot inspect organization secret values or npm package trusted-publisher settings, so it cannot distinguish an expired token from an otherwise valid token whose owner lost publish rights."
    candidate_causes:
      - "config: duplicated skills Deno/JSR config files and implicit config discovery"
      - "environment: npm secret principal/permission outside repository authority"
    and_gate: "yes — completing this release requires both independent remediations: JSR must use the intended config, and npm must obtain external write authority."
- hypothesis: JSR and npm causes are confirmed and have distinct remediation owners.
- test: `node --test scripts/workflow-contracts.test.mjs` and `pnpm test:release-tooling` pass after the workflow repair.
- expecting: once the commit is merged, a manual JSR dispatch skips live core 0.32.0 and completes six pending versions; a rerun of Publish #210 succeeds only after npm write authority is restored.
- next_action: ship the JSR workflow repair; separately have an npm scope/package administrator restore the write-capable NPM_TOKEN or deliberately configure trusted publishing, then rerun the existing Publish release.

## Resolution

- root_cause: "Two independent release blockers: (1) Publish to JSR invokes an implicit Deno config lookup, which selects packages/skills/deno.json (stale 0.3.1 and no license) rather than the intended packages/skills/jsr.json (MIT, 0.3.2); the synchronizer skips deno.json whenever jsr.json exists. (2) npm Publish's credential has repeatedly been rejected with E404 at @napplet/core@0.32.0 after successful builds, so the credential's token/principal lacks npm publication authority."
- fix: "Applied the repository-owned JSR workflow repair: @napplet/skills is excluded from implicit recursive publishing and is published separately from packages/skills with `npx jsr publish --config jsr.json --allow-slow-types --allow-dirty`; added a workflow-contract regression test. An npm administrator must still restore/rotate the repository or selected organization NPM_TOKEN with a granular token authorized to publish each @napplet package, then rerun Publish #210. Do not add OIDC-only code unless the administrator first configures an npm trusted publisher for every affected package."
- verification: "JSR run 32993805758 successfully published @napplet/core@0.32.0 before failing at skills/deno.json; explicit jsr.json dry run simulated @napplet/skills@0.3.2 successfully; the committed workflow selection is covered by `node --test scripts/workflow-contracts.test.mjs` (4 pass) and `pnpm test:release-tooling` (4 pass); npm Publish #210 retry attempt 2 reproduced the identical E404 after rebuilding all packages; authoritative main-to-registry map identifies core as live, vite-plugin as already current, and six pending JSR versions."
