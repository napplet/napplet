<interfaces>
New public tooling contracts, each documented with `@param`, `@returns`, and `@example`:
- `BuildSigner.signEvent(template: UnsignedEvent): Promise<SignedEvent>`
- `BuildSigner.getPublicKey(): Promise<string>`
- `BuildSigner.close(): Promise<void>`
- `BuildSignerSession = { signer: BuildSigner; clientSecret: RedactedSecret; remotePubkey: string; relays: string[] }`
- `pairBuildSigner(options: PairBuildSignerOptions): Promise<BuildSignerSession>`
- `reconnectBuildSigner(options: ReconnectBuildSignerOptions): Promise<BuildSignerSession | undefined>`
- `SecretStore.get(key: string): Promise<string | undefined>`
- `SecretStore.set(key: string, value: string): Promise<void>`
- `SecretStore.delete(key: string): Promise<void>`
- `createPlatformSecretStore(options: PlatformSecretStoreOptions): Promise<SecretStore>` using an injected process/filesystem adapter to preserve macOS Keychain, Linux Secret Service, Windows Credential Manager, and deliberate file-store fallback semantics across Node and Deno.
- `TerminalAdapter.showQr(value: string): Promise<void>`, `readLine(prompt: string, signal: AbortSignal): Promise<string>`, and `writeStatus(message: SafeStatus): void`

NIP-46 operations integrated here are `connect`, `get_public_key`, and `sign_event` for Blossom kind 24242 authentication. Pairing transport may receive kind 24133 NIP-46 responses. Other NIP-46 operations remain outside this capability boundary as recorded in `COVERAGE.md`.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Terminal → pairing coordinator | QR values and pasted bunker URIs enter the process from an operator-visible channel. |
| Build tool → NIP-46 relay | Pairing requests and signed-event requests traverse untrusted relays. |
| Process → OS secret store | The nbunksec leaves memory only through a protected platform adapter. |
| Signer response → build tool | Remote pubkeys, capabilities, and signed events must be authenticated before use. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-162-07 | Information Disclosure | nbunksec, bunker URI, and client secret | high | mitigate | Tasks 1–2 use redaction-safe values, protected SecretStore only, abort cleanup, and exhaustive log/error/serialization snapshots. |
| T-162-08 | Elevation of Privilege | NIP-46 authorization request | high | mitigate | Task 1 limits requests to `get_public_key` and `sign_event` kind 24242 and rejects every other event kind locally. |
| T-162-09 | Spoofing | NIP-46 relay responses | high | mitigate | Task 1 correlates request IDs, validates remote pubkey, verifies signed events, enforces timeouts, and closes stale subscriptions. |
| T-162-10 | Tampering | Stored signer session | high | mitigate | Tasks 1–2 parse and validate nbunksec fields, bind expected remote identity, and write only after successful verified pairing. |
| T-162-11 | Denial of Service | QR/paste race and relay subscriptions | medium | mitigate | Task 2 uses a shared abort hierarchy, bounded timeouts, first-success semantics, and deterministic cleanup tests. |
| T-162-SC | Tampering | npm/JSR package resolution | high | mitigate | Task 3 permits only identities and versions marked `[OK]` by the research Package Legitimacy Audit and rechecks lockfile resolution before install. |
</threat_model>
