<interfaces>
Plugin option finalized by this plan:
- `largeAssetOptimization?: 'auto' | false` on `Nip5aManifestOptions`; default is `'auto'`, threshold is not configurable.

New Node adapter and report contracts:
- `createNodeOptimizationServices(options: NodeOptimizationOptions): OptimizationServices`
- `NodeOptimizationOptions` accepts injected terminal, protected secret store, relay client, DNS resolver, fetch, clock, and logger for tests; production defaults are Node implementations.
- `OptimizationReport` exposes trigger bytes, final bytes, selected/preserved assets, safe status/reason codes, normalized server origins, verified upload hashes, and commit status—never secret or authorization material.

Canonical artifact surface:
- Public resource references are only `blossom:sha256:<64 lowercase hexadecimal>`.
- Runtime calls are only the accepted/proposed NAP-RESOURCE `resource.bytes` and `resource.bytesMany` messages.
- Mapping source identity, byte length, MIME, and loader metadata remain private JavaScript in signed `/index.html`; they are not NIP-5A tags or shell API.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vite configuration → plugin | User callbacks and options can conflict with controlled asset-reference handling. |
| Node process → signer/credential store | QR/paste/session reuse and kind-24242 signing handle high-value secret material. |
| Node network adapters → relays/Blossom | Untrusted events, URLs, DNS, redirects, HTTP bodies, and descriptors enter the build. |
| Optimizer → filesystem/manifest | A multi-step external upload drives destructive local artifact changes and aggregate hashing. |
